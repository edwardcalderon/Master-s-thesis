\section{Experimental design and falsification}

The design will use common random seed pairs where compatible, reduced parameter
sweeps, sensitivity analysis with uncertainty intervals, and preregistered
classification criteria. The number of replications will be set from convergence and
estimator precision, not from a universal rule of thirty. To avoid selection bias,
confirmation configurations will be kept separate from those used for model selection.

\subsubsection{Stochastic selection ABM}

configured contrasts. The same pre-generated noise schedule is shared across paired

\subsubsection{Held-out diagnostic for H1c}

Run \texttt{cex-dex-h1c-43e446f04adf} fits four condition-specific maps to 48,000
selection transitions at shocks $\pm0.1$, then applies them without refitting to 300
new seeds and shocks $\pm0.05$. All four fitted matrices were Schur-stable. The
Schur-based rule predicted contraction in all eight condition/shock groups, while
only three groups had a majority of contracting trajectories: agreement was $3/8$
($37.5\%$). Mean one-step RMSE was 0.01837 for signed excess $d$ and 0.00840 for
normalized pressure $z$; the selection $R^2$ for the $z$ equation was near zero across
conditions. Thus this map is a weak classifier in this representative model. The
holdout varies seeds and shock magnitude only; it does not test new agent rules,
capacity levels, fee regimes, or market data.

The current evidence supports only a narrow mechanical statement: in these exact
CPMM configurations, capacity limits alter correction speed and lower reserves
increase fixed-sale impact. It does not establish a general effect of adaptive LP
behavior, confirm H1c, calibrate a market parameter, or validate any hypothesis
externally. H1a and H1b remain to be tested across the agreed operating regions with
the reviewed agent design; H1c's present disagreement is retained as a limitation,
not hidden by the selection results.

\section{Reproducible playground and technology transfer}

\subsection{Architecture}

The current prototype is implemented in standard-library Python. Its deterministic
runner models an exogenous CEX reference, a two-reserve CPMM, a log no-arbitrage band,
capacity-limited arbitrage, fixed-sale depth comparisons, and a one-shot LP withdrawal
rule. A separate stochastic selection runner adds finite-wallet noise and trend/panic
traders, a bounded arbitrageur, and static/adaptive LP conditions. It uses a shared
pre-generated order schedule for paired comparisons and remains a representative-agent
selection model, not the full heterogeneous population in the research design. Shocks,
policy parameters, event timing, and horizons are configured explicitly. Run outputs
include configurations, trajectories, summaries, metadata, and artifact checksums.

\subsection{Canonical implementation reference}

The public, versioned architecture reference is the \textit{Master-s-thesis}
repository \cite{calderon2026repository}. The bilingual compilable manuscript is in
\texttt{thesis/}; the deterministic and stochastic MVP, configurations, and analysis
scripts are in \texttt{experiments/cex\_dex\_mvp}. Each run records its configuration,
source checksums, seeds, and artifact checksums. Local outputs can be regenerated with
the commands in the reproducibility log. No branch, URL, or synthetic result is
interpreted as empirical market evidence.

\subsection{Reproduction contracts}

\begin{enumerate}
  \item Versioned JSON configurations specify model parameters and economic units.
    The MVP uses only the Python standard library (Python 3.10 or newer).
  \item The invariant command checks positive reserves, both CPMM swap directions,
    proportional-withdrawal price preservation, arbitrage direction and capacity,
    paired external paths and noise schedules, and stochastic asset conservation.
    It currently covers 2,654 deterministic states and a 504-state stochastic smoke
    selection. Broader property-based and continuous-integration checks remain work.
  \item Stable commands for the deterministic run, checks, sweep, stochastic selection,
    and H1c analysis are listed in the reproducibility log. The tracked configurations
    and protocols define the comparison and output contracts.
  \item Run metadata records the run ID, model or analysis version, configuration and
    source hashes, runtime, seed set, and generated-artifact checksums. Larger generated
    outputs are kept outside Git locally and can be recreated with the documented
    commands.
  \item Results remain synthetic. A bounded public-market dataset with a documented
    license, provenance, timestamps, and ingestion scripts is future work, as is
    validation against on-chain or exchange execution records.
\end{enumerate}

\subsection{Relationship to open market software}

The theoretical market will use CPMM mechanics compatible with a Uniswap v2-style AMM
\cite{adams2020uniswap,angeris2020cfmm}; it will not be extrapolated to concentrated
liquidity positions in Uniswap v3/v4 without testing. Swaps are proposed to be checked
against locally deployed reference contracts using Foundry/Anvil and Web3 libraries,
under controlled configuration and without real funds. For the CEX reference, public
series may be obtained through market adapters such as CCXT or a public exchange API,
after checking licenses, pair identity, latency, spreads, and timestamps. An optional
second level is replay of indexed on-chain events (for example, compatible pool Swap
and Sync records) to validate execution-error magnitudes. Running mainnet nodes,
advanced MEV, or live trading is not required.
